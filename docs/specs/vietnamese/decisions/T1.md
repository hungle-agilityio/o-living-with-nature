# Decisions during build: T1 (#107)

| Question | Chosen | Rejected | Why | From |
|---|---|---|---|---|
| Where does a template get its language? | From `request.LANGUAGE_CODE` (set by the middleware from the address), then the context's `lang`, then English | `get_language()` alone | A translation left active in a thread must not leak into a render with no request (for example `media.html` rendered directly), which stays English | build |
| What does `{% text %}` escape? | `&`, `<`, `>` and `"`, not `'` | Django's `escape` (which also turns `'` into `&#x27;`) | The English 404 line "isn't" is kept as written, and `"` becomes `&quot;` as in the footer note | build |
| How does the chip in `floor_plan.html` read? | Through `{% text "shell" "chip_photo" %}` | Leave it English | The file is outside the issue's list, but every chip on `/vi/` must be Vietnamese; only that chip changed | build |
| Where do the footer preview link texts come from? | Their own keys `preview_dawn` to `preview_night` | The theme name as is | The Vietnamese words ("bình minh") differ from the `?t=` value, which stays `dawn` | build |
| Name of the context processor | `pages.context_processors.page_language` | `language` | The module `pages.language` is imported there; one name for both would hide it | build |
| The floor-plan dialog's `aria-label="Photo"` and its credit and alt texts on `/vi/` | Left to #105 (T2), which owns `floor_plan.html` and the chapter 01 texts | Translate them here | texts.md puts the floor-plan texts in T2; T1 changes only the chip, which a T1 test needs | build |
| Where do `/` and `/vi/` live in the search tags? | `seo.py` takes them from `language.home_path` | A second copy of the paths in `seo.py` | One place names each language's address (code review) | build |
| How do the photo tags reach the language? | `photo`, `area_loop` and `floor_plan` take the context and pass `lang` to the included template | A global lookup in the template | Inclusion templates get a fresh context with no request | build |
