# Decisions during build: T3 (#106)

| Question | Chosen | Rejected | Why | From |
|---|---|---|---|---|
| Where do the Vietnamese owner lines (greeting, reply line, price line, Call label) live? | In `owner_content/services.py`, beside the English ones | Keys in `pages/texts/` | They are built from the owner's values (first name, reply time, prices); spec AC5 excepts them from the texts modules | build |
| Where does the view get the language for the owner's settings? | `language.of_request(request)` once, passed to both `seo.head_for` and `site_settings` | Reading it again in the service | Same source as the search tags, so the head and the body never disagree | build |
| How does `owner_content` know the language? | `site_settings(language)` takes a plain code (`"vi"`, anything else is English) | Importing `pages.language` | The owner_content app does not depend on the pages app | build |
| Where do the spaces around an accent word stay? | In the templates, between the `{% text %}` tags | Inside the keys | `/` renders byte-identical and the keys hold only the words | build |
| The `05` marker of chapter 05 | Stays literal in `contact.html` | A key | It is the same in both languages (texts.md) | build |
| Does `PARTS` (`pages/texts/__init__.py`) list the new parts? | No, left as it is | Adding `rent`, `faq`, `contact` | Nothing reads `PARTS`; the key test finds every texts module by itself, and the file is not in this issue's list (T2 adds its parts in parallel) | build |
| The `{% load texts %}` of `faq.html` and `contact.html` | On the line of `{% comment %}` | A line of its own | A line of its own adds a blank line to the rendered `/` | build |
